## 패턴 4. Phase 작업 범위 구분

> **영역**: 1. AI 역할 축소 · **빈도**: ★ · **흡수**: #32 작업 범위 구분

### 기본 분류
- 영역: 1. AI 역할 축소
- 패턴: 4. Phase 작업 범위 구분
- 실행 양식: 자동화 범위와 사람 운영 범위 구분

### 한 줄 기준

자동 반영 가능한 영역과 사람이 자연어로 운영해야 하는 영역이 섞여 있을 때 적용한다.

### 적용 신호

- 자동화 가능한 단계와 케이스마다 달라지는 제약이 섞여 있다.
- 고객사·수강생 수준·보안·시수처럼 케이스마다 달라지는 제약이 있다.
- 도구 안에 넣으면 본질보다 예외 처리가 커진다.
- 표준화 영역과 자유 운영 영역을 나누면 더 단순해진다.

### 비적용 신호

- 모든 제약을 도구가 항상 정확히 반영할 수 있다.
- 자유 운영 영역이 아니라 명확히 자동 반영 가능한 영역이다.
- 밖으로 뺀 영역을 LD가 어떻게 다룰지 안내할 수 없다.
- 자동화 범위와 사람 운영 범위의 입력·출력을 구분할 수 없다.

### 필요한 입력값

- 전체 업무 단계 / 자동화 가능 단계 / 케이스마다 달라지는 제약 / 사람이 대화로 조정할 영역 / 최종 산출물 예시

### 판단 기준

- 이 제약을 도구가 항상 정확히 반영할 수 있는가?
- 케이스마다 달라지는 제약인가? 도구 안에 넣으면 본질보다 예외 처리가 커지는가?
- 표준화 영역과 자유 운영 영역을 나누면 더 단순해지는가?

### 추천 액션

- 실행 시점: 도구 안에 넣을 영역과 사람이 조정할 영역이 섞여 있을 때
- 실행 주체: 세션 담당자와 LD
- 액션 내용: 전체 업무 단계를 자동화 범위와 사람 운영 범위로 나눔·각 범위에 입력·출력 적음·도구 밖 제약 목록과 LD 조정 질문 붙임
- 완료 기준: 자동화 범위 표 / 사람 운영 범위 표 / 도구 밖 제약 목록 / LD 조정 질문 정리

### 주의사항

- 오분류 위험: 자동화 범위를 넓히는 것보다 경계를 선명히 잡는 것이 더 중요할 때가 있음
- 헷갈리는 패턴: 자동화 비대상 인정(패턴 13) — Phase 작업 범위는 전체 업무 안에서 경계 설계, 자동화 비대상은 특정 항목을 자동화하지 않기로 남기는 결정
- 쓰면 안 되는 조건: 밖으로 뺀 영역을 LD가 어떻게 다룰지 안내하지 않는 경우
- 추가 주의: "도구가 못 한다"가 아니라 "도구에 넣지 않는 편이 더 낫다"는 판단일 수 있음

### 대표 사례

- 이수빈 커리큘럼 자동화: Phase 2는 표준 원형·모듈 블록 생성으로 두고, 시수·수준·보안 같은 제약은 Phase 3에서 LD가 자연어로 운영하도록 분리

### 정보 부족 시 확인 질문

- 전체 업무 단계 중 자동 반영 가능한 단계는 어디인가요?
- 케이스마다 달라지는 제약은 무엇인가요?
- 도구 안에 넣으면 예외 처리가 너무 커지는 항목은 무엇인가요?
- 사람이 자연어로 조정해야 하는 영역은 무엇인가요?
- 도구 밖으로 뺀 제약을 LD가 어떻게 다룰지 질문이 있나요?
