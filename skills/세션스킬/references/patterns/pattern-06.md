## 패턴 6. AI 처리 chain 분담

> **영역**: 1. AI 역할 축소 · **빈도**: ★ · **흡수**: #34 LLM chain 다중 오케스트레이션

### 기본 분류
- 영역: 1. AI 역할 축소
- 패턴: 6. AI 처리 chain 분담
- 실행 양식: LLM chain 단계 계약 정리

### 한 줄 기준

코드나 DB보다 여러 AI 스킬의 순차 실행으로 산출물이 만들어지는 구조일 때 적용한다.

### 적용 신호

- 정량 코드 자리보다 AI 판단·생성 단계가 중심이다.
- 한 번의 프롬프트가 아니라 여러 단계가 순차적으로 이어진다.
- 중간 산출물이 다음 단계의 입력으로 쓰인다.
- 메인 스킬과 하위 스킬의 역할이 구분되어 있다.
- 단계별 입력·출력 계약이 필요하다.

### 비적용 신호

- 한 번의 프롬프트나 단일 코드 처리로 충분하다.
- 중간 산출물이 다음 단계 입력으로 이어지지 않는다.
- 메인 스킬과 하위 스킬의 역할을 구분할 수 없다.
- 단계가 많아졌지만 품질 검증 지점이 없다.

### 필요한 입력값

- 메인 입력값 / 중간 산출물 목록 / 각 단계별 AI 스킬·프롬프트 / 단계 간 전달 값 / 최종 출력 형식

### 판단 기준

- 정량 코드 자리보다 AI 판단·생성 단계가 중심인가?
- 한 번의 프롬프트가 아니라 여러 단계가 순차적으로 이어지는가?
- 중간 산출물이 다음 단계의 입력으로 쓰이는가?
- 메인 스킬과 하위 스킬의 역할이 구분되어 있는가?

### 추천 액션

- 실행 시점: 여러 AI 스킬·프롬프트가 순차 실행되는 구조 설계 시
- 실행 주체: 세션 담당자 또는 AI
- 액션 내용: 전체 chain 지도·단계별 입력·출력 표·메인 오케스트레이터 역할·하위 스킬 역할·단계별 검증 포인트 정리. 중간 산출물 전달 방식 명시
- 완료 기준: chain 지도·단계별 입력·출력 계약·검증 포인트 정리

### 주의사항

- 오분류 위험: 단계가 많아지면 어디서 품질이 무너졌는지 찾기 어려움
- 헷갈리는 패턴: 학습→구현→진화 3단계(패턴 9) — LLM chain은 여러 AI 단계의 구조 계약, 체크리스트+프롬프트는 LD가 직접 실행할 문장 묶음. 또 LLM 동적 도구 호출(패턴 30) — AI 처리 chain 분담은 미리 정한 순서대로 실행하는 고정 chain, LLM 동적 도구 호출은 LLM이 상황에 따라 도구를 선택하는 동적 호출
- 쓰면 안 되는 조건: 메인 스킬과 하위 스킬의 입력·출력 계약이 흐린 경우
- 추가 주의: 자동 검증을 통과해도 최종 본문 검토는 별도 필요

### 대표 사례

- 이수빈 커리큘럼 자동화: Phase 1·Phase 2 공정 스킬과 메인 오케스트레이터가 연결된 14~15개 스킬 chain. 코드 스크립트보다 AI 스킬들의 순차 실행이 본체

### 정보 부족 시 확인 질문

- 전체 산출물은 여러 AI 단계가 순서대로 이어져 만들어지나요?
- 각 단계의 입력과 출력은 무엇인가요?
- 중간 산출물이 다음 단계에 어떻게 전달되나요?
- 메인 스킬과 하위 스킬의 역할이 구분되어 있나요?
- 단계별로 어디에서 품질을 확인하나요?
