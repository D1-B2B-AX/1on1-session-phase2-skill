## 패턴 3. Core·Shell 분리

> **영역**: 1. AI 역할 축소 · **빈도**: ★★ · **흡수**: #6 Core/Shell 분리

### 기본 분류
- 영역: 1. AI 역할 축소
- 패턴: 3. Core·Shell 분리
- 실행 양식: Core/Shell 경계 분리

### 한 줄 기준

사람이 반드시 정해야 하는 판단과 AI가 실행해도 되는 구현을 분리해야 할 때 적용한다.

### 적용 신호

- 만들 대상, 데이터 모양, 사용자 행동을 사람이 정해야 한다.
- AI가 구현할 파일, 스크립트, UI 범위는 따로 잡을 수 있다.
- "이 정도면 완성인지"를 LD가 판단해야 한다.
- 사람 판단 영역과 AI 실행 영역이 섞이면 도구가 업무와 어긋날 위험이 있다.

### 비적용 신호

- 만들 대상, 데이터 모양, 사용자 행동이 이미 명확히 고정되어 있다.
- 문제의 핵심이 구현 경계가 아니라 코드/LLM 역할 분리나 데이터 흐름 점검에 있다.
- LD가 정해야 할 Core 판단 없이 단순 반복 구현만 남아 있다.
- AI에게 맡길 Shell 범위가 아직 정해지지 않았다.

### 필요한 입력값

- 만들 대상 / 데이터 모양 / 사용자 행동 / AI가 구현할 파일·스크립트·UI 범위 / 합격 기준

### 판단 기준

- "무엇을 만들지"·"어떤 데이터가 맞는지"·"이 정도면 완성인지"는 LD 판단이다.
- "어떻게 코딩할지"·"어떻게 렌더링할지"·"반복 구현"은 AI Shell 영역이다.

### 추천 액션

- 실행 시점: 구현 전 설계 단계에서 만들 대상과 구현 범위가 섞여 있을 때
- 실행 주체: 세션 담당자와 LD
- 액션 내용: 만들 대상·데이터 모양·사용자 행동을 Core로 적고, 코드 작성·연결·렌더·테스트를 Shell 범위로 따로 적음. Core별 합격 기준 붙임
- 완료 기준: Core 3가지와 Shell 범위 분리·각 Core에 LD 확인 합격 기준 정리

### 주의사항

- 오분류 위험: Core를 AI에게 넘기면 도구가 그럴듯해도 LD 업무와 어긋남
- 헷갈리는 패턴: 코드·LLM 분리(패턴 7) — Core/Shell은 사람 판단과 AI 구현 경계, 코드·LLM 분리는 정량 계산과 LLM 해석 경계
- 쓰면 안 되는 조건: LD가 정해야 할 판단이 비어있는데 AI 구현부터 시키는 경우
- 추가 주의: Shell을 사람이 과도하게 붙잡으면 자립 속도 느려짐

### 후속 표기 보정 (3-1 영역에서는 후속 패턴으로만 표시)

입력에 *AI 자동화 vs 사람 판단* Core·Shell 신호가 있어도 아래 조건이 모두 해당하면 패턴 3을 *주 패턴*이나 *즉시 실행 양식*으로 올리지 않고 *후속 패턴*으로만 표시한다.

- 현재 단계가 3-1 세션 전/초반 진단이다.
- 도메인 학습용 하네스(패턴 16)가 아직 없다.
- 페인 one sentence(패턴 10)가 아직 확정되지 않았다.
- 만들 대상·데이터 모양·사용자 행동이 아직 정해지지 않았다.

이 경우 출력 예: `후속: 학습용 하네스와 페인 컨펌 완료 후 Core·Shell 경계 점검`. 도메인 구조와 페인이 정해지기 전에 자동화 범위를 결정하면 잘못된 경계가 박힌다.

### 대표 사례

- 김동찬: LD가 3개 기능과 합격 기준 정함·AI가 구현
- 이현진 딜판단: 결정론 기준과 LD 직관 grounding은 사람 판단·Python과 LLM은 구현 영역

### 정보 부족 시 확인 질문

- 이 도구에서 LD가 반드시 직접 정해야 하는 것은 무엇인가요?
- 만들 대상·데이터 모양·사용자 행동이 각각 분리되어 있나요?
- AI에게 맡겨도 되는 구현 범위는 어디까지인가요?
- 무엇이 되면 완성이라고 볼지 LD가 판단할 기준이 있나요?
- 지금 AI가 판단까지 하고 있나요, 아니면 구현만 하고 있나요?
