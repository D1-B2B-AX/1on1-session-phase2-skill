## 패턴 26. 암묵 SOP 추출

> **영역**: 15. 구현형 형식지 추출 · **빈도**: ★ · **흡수**: #26 구현형 형식지 확인

### 기본 분류
- 영역: 15. 구현형 형식지 추출
- 패턴: 26. 암묵 SOP 추출
- 실행 양식: 구현물 안 형식지 추출

### 한 줄 기준

문서형 SOP는 없지만 코드·화면·데이터 구조·AI 구현 대화 안에 반복 가능한 형식지가 이미 있을 때 적용한다.

### 적용 신호

- 문서형 SOP는 없다.
- 기존 대시보드·코드·HTML·API·저장 layer가 있다.
- AI와 주고받은 구현 대화 안에 반복 구조가 있다.
- 구현물 안에 입력값·판단 기준·출력 형식이 박혀 있다.
- 다음 과제가 새 형식지 작성이 아니라 운영 안정화일 수 있다.

### 비적용 신호

- 기존 구현물이나 구현 대화가 없다.
- 실제로 입력값·판단 기준·출력 형식이 구현물 안에 남아 있지 않다.
- 구현물이 있어도 운영 검증 체계가 없다.
- 지금 필요한 것은 구현형 형식지 추출이 아니라 데이터 흐름 점검이다.

### 필요한 입력값

- 기존 대시보드·코드·HTML / API·저장 layer / 와이어프레임 / AI와 주고받은 구현 대화 / 정기 업데이트·오류 수정·재배포 미완 목록

### 판단 기준

- "형식지 없음"으로 오진하면 이미 만든 구조를 버리게 된다.
- 실제로는 구현물 안에 입력값·판단 기준·출력 형식이 박혀 있다.
- 다음 과제는 새 형식지 작성이 아니라 운영 안정화다.
- 구현물이 있다고 운영 가능하다는 뜻은 아니다.

### 추천 액션

- 실행 시점: 형식지 문서는 없지만 기존 구현물이나 대화가 있는 것을 확인한 때
- 실행 주체: 세션 담당자 또는 LD
- 액션 내용: 기존 구현물에서 입력값·판단 기준·출력 형식·구현 상태를 표로 추출. 정기 업데이트·오류 수정·재배포의 미완 목록 따로 적음
- 완료 기준: 구현형 형식지 표·운영 안정화 미완 목록 정리

### 주의사항

- 오분류 위험: 구현물이 있다고 운영 가능하다는 뜻은 아님
- 헷갈리는 패턴: 공통 컨텍스트 문서화(패턴 16) — 구현형 형식지 추출은 기존 구조를 추출하는 단계(-1→1), 공통 컨텍스트 문서화는 새로 만드는 단계(0→1). 또 수집·전달 5단계 점검(패턴 19) — 형식지 추출은 기존 구조를 추출하는 단계, 5단계 점검은 운영 데이터 병목 찾음
- 쓰면 안 되는 조건: 기존 구현물 안에 판단 기준이나 출력 형식이 실제로 없는 경우
- 추가 주의: 구현형 형식지는 운영 검증 체계와 별개

### 대표 사례

- 김민선: 강사 대시보드는 문서형 SOP는 없었지만 HTML 대시보드·Redis/JSON 저장·API·수집 스크립트 안에 형식지가 있음. 그래서 새 형식지 작성이 아니라 운영 데이터 흐름 점검으로 진입

### 정보 부족 시 확인 질문

- 문서형 SOP가 없어도 이미 만든 대시보드·코드·화면이 있나요?
- 구현물 안에서 입력값·판단 기준·출력 형식을 찾을 수 있나요?
- AI와 구현 대화에 반복 구조가 남아 있나요?
- 지금 필요한 것은 새 문서 작성인가요, 운영 안정화인가요?
- 정기 업데이트·오류 수정·재배포 중 아직 안 된 것은 무엇인가요?
