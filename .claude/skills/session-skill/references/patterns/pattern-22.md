## 패턴 22. 정책·권한 막힘 돌파

> **영역**: 11. 권한 벽 우회 · **빈도**: ★ · **흡수**: #10 권한 벽 우회

### 기본 분류
- 영역: 11. 권한 벽 우회
- 패턴: 22. 정책·권한 막힘 돌파
- 실행 양식: 허용 가능한 우회 경로 설계

### 한 줄 기준

조직 정책이나 권한 때문에 원래 연결 방식이 막혔을 때 적용한다.

### 적용 신호

- 조직 정책이나 계정 권한 때문에 원래 연결 방식이 막혔다.
- 대체 가능한 계정·서비스·수동 경로를 검토할 수 있다.
- 보안상 금지되는 행동을 피해야 한다.
- 정책을 뚫는 것이 아니라 허용 가능한 다른 경로를 설계해야 한다.

### 비적용 신호

- 권한이나 정책 문제가 아니라 데이터 구조나 구현 오류가 원인이다.
- 보안상 금지되는 행동을 해야만 가능한 경로다.
- 대체 계정·서비스·수동 경로가 전혀 없다.
- PII 저장 원칙과 접근 권한을 검토하지 않았다.

### 필요한 입력값

- 막힌 권한·정책 / 대체 가능한 계정·서비스·수동 경로 / 보안상 금지되는 행동 / PII 저장 원칙 / 접근 권한 범위

### 판단 기준

- 정책을 뚫으려 하지 않는다.
- 조직 보안 원칙을 존중하면서 목표 달성 경로를 새로 설계한다.
- 우회 경로도 운영 가능해야 한다.
- PII 저장 원칙과 접근 권한은 별도로 검토해야 한다.

### 추천 액션

- 실행 시점: 정공법 연결이 조직 정책이나 계정 권한으로 막힌 직후
- 실행 주체: 세션 담당자와 LD
- 액션 내용: 막힌 권한·금지 행동·허용 가능한 대체 경로를 표로 나눔. 각 대체 경로에 운영 가능성·보안 원칙·PII 저장 여부·접근 권한 리스크 붙임
- 완료 기준: 보안 회피가 아닌 허용 가능한 우회 경로와 운영 리스크 문서화

### 주의사항

- 오분류 위험: "우회"를 보안 회피로 이해하면 위험
- 헷갈리는 패턴: 데이터 소스 결정 3단(패턴 20) — 권한 벽 우회는 접근 경로 문제, 데이터 소스 결정은 저장 방식 문제
- 쓰면 안 되는 조건: 조직 보안 원칙·PII 원칙을 확인하지 않은 상태
- 추가 주의: 우회 경로도 실제 운영 가능한 방식이어야 함

### 대표 사례

- 김동찬: Day1 회사 계정에서 Apps Script·Drive API가 막혀 AX 공용 개인 Gmail로 GCP 프로젝트와 Service Account를 발급하는 경로 설계
