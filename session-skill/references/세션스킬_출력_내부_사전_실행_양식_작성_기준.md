# 세션스킬 출력·내부 사전·실행 양식 작성 기준

## 1. 목적

이 문서는 새 세션 형식지를 입력했을 때 SKILL이 어떤 결과를 출력해야 하는지, 그리고 그 출력을 만들기 위해 내부 사전에는 어떤 정보가 들어가야 하는지를 정의한다.

구분은 아래와 같다.

| 구분 | 목적 | 읽는 주체 |
|---|---|---|
| 최종 출력 양식 | 세션 담당자가 바로 다음 행동을 결정할 수 있게 보여주는 결과 | 사람 |
| 내부 사전 양식 | SKILL이 분류·근거·액션·주의사항을 판단하기 위해 참고하는 데이터 | AI |

최종 출력은 짧고 실행 가능해야 한다.  
내부 사전은 AI가 판단하기 쉽도록 실행 양식 단위로 자세히 작성한다.

분류 체계는 `세션스킬_내부사전_v1차통합_260520.md`의 15개 영역·30개 패턴을 기준으로 삼고, 내부 사전 작성 단위는 37개 실행 양식으로 둔다.

내부 사전을 작성한 뒤에는 `실행 양식 사전 작성 검수표.md`로 비적용 신호, 추천 액션, 주의사항, 정보 부족 시 확인 질문이 기준에 맞게 작성됐는지 점검한다.

## 2. 최종 출력 양식

SKILL이 세션 담당자에게 보여주는 최종 출력은 아래 4항목과 선택 입력용 회고 안내로 구성한다.

```md
## 추천 패턴 분류 결과

### 1. 분류 결과

- 현재 단계 추정:
- 영역:
- 패턴:
- 실행 양식:

### 2. 분류 근거

-

### 3. 다음 액션

-

### 4. 주의사항

-

### 5. 회고 안내 (선택 입력)

- 추천한 영역·패턴이 LD에게 정합했는가?
- 잘못 적용된 영역이나 패턴이 있었는가?
- 같이 진행된 다른 영역·패턴이 있었는가?
- SKILL 정정 영역을 발견했는가?
```

### 2-1. 분류 결과

`분류 결과`에는 현재 형식지가 어느 단계에 있는지, 그리고 어떤 영역/패턴/실행 양식에 가까운지를 적는다.

```md
- 현재 단계 추정:
- 영역:
- 패턴:
- 실행 양식:
```

영역과 패턴은 15개 영역·30개 패턴 체계를 따른다. 실행 양식은 37개 실행 양식 중 실제 적용 단위로 고른다.

단독 영역 5건은 영역과 패턴이 사실상 같은 카드로 읽히므로 아래처럼 표시할 수 있다.

```md
- 영역(패턴): [영역명] — [패턴명]
- 실행 양식: [실행 양식명]
```

### 2-2. 분류 근거

`분류 근거`에는 아래 내용을 자연어로 정리한다.

- 현재 단계로 판단한 근거
- 이 영역/패턴/실행 양식으로 판단한 근거
- 입력 형식지에서 포착한 신호

단, 최종 출력에서는 내부 사전의 모든 신호를 나열하지 않는다. 세션 담당자가 납득할 수 있는 핵심 근거만 적는다.

### 2-3. 다음 액션

`다음 액션`에는 현재 단계에서 세션 담당자가 바로 해야 할 일을 적는다.

- 현재 단계에서 바로 해야 할 일
- 추가로 확인할 질문
- 확보해야 할 자료 또는 보완할 형식지 항목
- 아직 하지 말아야 할 일

기본 관점은 세션 초반 또는 형식지 정리 중 상황에 둔다. 다만 입력 형식지가 이미 구현 전·구현 중·검증 전 단계로 보이면 그 단계에 맞는 액션을 제안한다.

최종 출력의 `다음 액션`은 방향 안내 수준으로 쓴다. 내부 사전의 추천 액션에는 실행 시점·주체·내용·완료 기준을 자세히 두되, 최종 출력에서는 프롬프트 전문, 코드 블록, 산출물 표 양식을 길게 노출하지 않는다.

### 2-4. 주의사항

`주의사항`에는 이 분류를 잘못 적용했을 때 생기는 위험을 적는다.

- 이 분류를 잘못 적용할 때 생기는 위험
- 비슷하지만 다른 패턴과 헷갈릴 지점
- 다음 단계로 넘어가기 전 확인할 조건

주의사항은 단순 경고가 아니라, 세션 담당자가 오진을 피할 수 있게 쓰는 항목이다.

### 2-5. 회고 안내

`회고 안내`는 세션 후 선택 입력 항목이다. 필수 입력은 아니지만, SKILL 기준을 다음 세션에서 보정할 수 있도록 아래 4가지를 짧게 안내한다.

- 추천한 영역·패턴이 LD에게 정합했는가?
- 잘못 적용된 영역이나 패턴이 있었는가?
- 같이 진행된 다른 영역·패턴이 있었는가?
- SKILL 정정 영역을 발견했는가?

## 3. 현재 단계 추정 기준

이 기준은 최종 출력에 매번 전부 노출하지 않는다.  
SKILL이 `현재 단계 추정`을 판단할 때 내부 기준으로 사용한다.

### 3-1. 세션 전/초반 진단

- 업무 유형, 현재 해결 방식, 페인 정도만 있음
- 입력값/출력값이 불명확함
- 정답본·판단 기준·검증 방식이 아직 비어 있음

### 3-2. 형식지 정리 중

- 입력값과 출력물은 일부 있음
- 사람이 아는 판단 기준이 일부 드러남
- 어떤 패턴을 적용할지 고르는 단계
- 아직 구현 방식이나 검증 기준은 미정

### 3-3. 구현 전 설계

- 입력값, 출력물, 판단 기준이 꽤 정리됨
- 어떤 도구나 `SKILL.md`로 만들지 논의 중
- 액션 블록이나 코드/프롬프트 설계가 필요함

### 3-2·3-3. 동시 진행 가능

`형식지 정리 중`과 `구현 전 설계`는 동시에 진행될 수 있다. 입력값·출력물과 판단 기준을 정리하면서 곧바로 도구, 코드, `SKILL.md`, 프롬프트 설계까지 논의되는 경우에는 `현재 단계 추정: 3-2·3-3 동시 진행`으로 표시한다.

이 경우 `다음 액션`은 해결 방향 결정 액션과 구현 방향 결정 액션을 함께 제시하되, 둘을 섞지 않는다.

### 3-4. 구현 중

- 이미 `SKILL.md`, 코드, 프롬프트, 대시보드 등 구현물이 있음
- 수정, 반영, 재실행, 버전업 이야기가 나옴

### 3-5. 검증/운영 전

- 구현물은 있고, 실제 사용·재사용·정확성·운영 반영을 확인해야 함
- PASS/FAIL, Core, Golden Case, 사용 로그, 모수 이야기가 나옴

## 4. 내부 사전 양식

내부 사전은 AI가 최종 출력을 만들기 위해 참고하는 판단용 데이터다.  
작성 단위는 패턴이 아니라 실행 양식이다.

기본은 아래 압축 양식을 사용한다. 모든 실행 양식에 풀버전을 강제하면 작성 부담이 커지므로, 헷갈리는 패턴이나 위험도가 높은 실행 양식만 확장 항목을 추가한다.

```md
## 실행 양식 ID. 실행 양식명

### 기본 분류

- 영역:
- 패턴:
- 실행 양식:
- 기존 실행 양식명:

### 한 줄 기준

-

### 적용 신호

최종 출력 `분류 근거`에 사용한다.

-

### 비적용 신호

최종 출력 `주의사항`에 사용한다.

비적용 신호는 이 실행 양식을 추천하지 않아야 하는 단서다.

기존 37개 실행 양식 본문을 내부 사전 양식으로 옮길 때는 기존 문장을 아래 기준으로 분리한다.

- 이 실행 양식이 맞는 경우 → 적용 신호 또는 판단 기준
- 비슷해 보이지만 이 실행 양식이 아닌 경우 → 비적용 신호
- 잘못 적용했을 때 생기는 위험 → 주의사항
- 정보가 부족해서 판단할 수 없는 경우 → 정보 부족 시 확인 질문

비적용 신호는 단순 경고가 아니라, “이 경우에는 이 실행 양식을 추천하지 않는다”로 판단 가능한 문장이어야 한다.

-

### 필요한 입력값

최종 출력 `다음 액션`에 사용한다.

-

### 판단 기준

최종 출력 `분류 근거`에 사용한다.

-

### 추천 액션

최종 출력 `다음 액션`에 사용한다.

모든 실행 양식에서 아래 4개 항목을 같은 깊이로 채운다. 어떤 실행 양식은 상세하고 어떤 실행 양식은 “LD가 정리한다” 수준으로만 쓰면, 세션 담당자가 SKILL을 그대로 따라가도 되는 영역과 추가 판단이 필요한 영역을 구분하기 어렵다.

- 실행 시점:
  - 언제 실행하는지 구체적으로 쓴다.
  - 예: 차이 목록 생성 후 / 형식지 초안 작성 직후 / 구현 전 설계 단계 / 검증 기준 정리 전
- 실행 주체:
  - 누가 실행하는지 쓴다.
  - 예: LD / 세션 담당자 / AI / 코치
- 액션 내용:
  - 실제로 무엇을 하는지 행동 단위로 쓴다.
  - `정리한다`, `확인한다`처럼 넓은 표현만 쓰지 말고, 무엇을 어떤 기준으로 정리·확인하는지까지 쓴다.
- 완료 기준:
  - 무엇이 끝나면 액션이 완료된 것으로 볼지 쓴다.
  - 예: 모든 차이에 LD 분류값과 판단 이유가 붙는다 / 입력값·출력값·판단 기준이 표로 채워진다

최종 출력 `다음 액션`에 사용한다.

-
```

`영역`과 `패턴`은 15개 영역·30개 패턴 좌표를 따른다. `실행 양식`은 실제 액션 단위로 유지한다.

### 4-1. 필요할 때만 추가하는 확장 항목

## 5. 작성 예시

아래 예시는 `영역 6. diff 룰 발견` 안의 실행 양식 하나를 내부 사전으로 작성한 예시다.

### 5-1. 내부 사전 예시: FORM-06-02. LD 차이 분류

#### 기본 분류

- 영역: 6. diff 룰 발견
- 패턴: 14. AI 초안·정답 차이 분류
- 실행 양식: LD 차이 분류
- 기존 실행 양식명: Diff 플레이형, Prompt 6규칙형

#### 한 줄 기준

AI 초안과 사람 정답본의 차이를 LD가 직접 보고, 규칙화할 차이와 보류할 차이를 나눌 때 적용한다.

#### 적용 신호

최종 출력 `분류 근거`에 사용한다.

- AI 초안과 사람 정답본이 모두 있다.
- 두 결과물 사이에 반복적인 차이가 보인다.
- LD가 정답 품질을 알고 있다.
- LD가 “왜 이렇게 고쳤는지” 판단할 수 있다.

#### 비적용 신호

최종 출력 `주의사항`에 사용한다.

- 사람 정답본이 없다.
- AI 초안과 사람 결과를 비교할 수 없다.
- LD가 차이를 직접 볼 시간이 없다.
- 차이가 단순 오탈자 수준이다.
- 이미 규칙이 명확히 정리되어 있다.

#### 필요한 입력값

최종 출력 `다음 액션`에 사용한다.

- AI 초안
- 사람 정답본
- 차이 목록
- 기존 `SKILL.md` 또는 규칙 문서
- LD가 차이를 분류할 시간

#### 판단 기준

최종 출력 `분류 근거`에 사용한다.

- 이 차이가 반복 가능한가?
- 조건을 문장으로 명확히 쓸 수 있는가?
- 개인 습관이나 취향에 가까운가?
- 케이스별 판단인가?
- 확실하지 않으면 보류할 수 있는가?

#### 추천 액션

최종 출력 `다음 액션`에 사용한다.

- 실행 시점: 차이 목록 생성 후
- 실행 주체: LD
- 액션 내용: 각 차이를 `(a) 조건 명확 / (b) 습관 / (c) 케이스바이케이스 / 보류`로 분류한다.
- 완료 기준: 모든 차이에 LD 분류값과 판단 이유가 붙는다.

#### 주의사항

최종 출력 `주의사항`에 사용한다.

- 오분류 위험: LD 분류 없이 AI가 바로 규칙을 만들게 하는 것
- 헷갈리는 패턴: Fresh 검증형
- 쓰면 안 되는 조건: 사람 정답본이 없거나 LD가 차이를 판단할 시간이 없는 경우
- 추가 주의: `(b) 습관`, `(c) 케이스바이케이스`, `보류` 항목은 `SKILL.md` 규칙으로 넣지 않는다.

#### 대표 사례

- 조여경 배포공지: AI 공지 초안과 실제 배포공지의 차이를 LD가 직접 `(a)/(b)/(c)/보류`로 분류했다.
- 손승완 자막교정기: 원본 SRT와 정답본 docx의 차이를 보고 사전, 정규식, AI 판단, 사람 검수 영역으로 나눴다.

#### 정보 부족 시 확인 질문

최종 출력 `다음 액션`에 사용한다.

- 사람이 만든 정답본이 있나요?
- AI 초안과 사람 정답을 나란히 비교할 수 있나요?
- LD가 각 차이에 대해 왜 고쳤는지 판단할 수 있나요?
- 기존 `SKILL.md`나 규칙 문서가 있나요?
- 신규 규칙 0개도 허용 가능한가요?

#### 확장 항목

- 우선순위: 높음
- 기대 산출물: 차이 분류표, `(a)/(b)/(c)/보류` 분류 결과, 규칙 후보와 미반영 항목 구분
- 헷갈리는 패턴과 구분 기준:
  - Fresh 검증형: Diff는 규칙을 만들기 전 차이를 보는 단계이고, Fresh 검증은 이미 만든 규칙을 새 자료에 돌려보는 단계다.
  - 자동화 비대상 인정형: 차이 분류 결과, 규칙화하면 안 되는 항목을 사람 영역으로 남길 때 함께 쓴다.
- 같이 자주 쓰이는 패턴: Prompt 6규칙형, 자동화 비대상 인정형, Fresh 검증형, 인라인 근거 메모형
- 병합된 기존 번호: 2, 28
- 별칭/기존 실행 양식명: Diff 플레이형, Prompt 6규칙형

---

### 5-2. 최종 출력 예시

```md
## 추천 패턴 분류 결과

### 1. 분류 결과

- 현재 단계 추정: 형식지 정리 중
- 영역: 6. diff 룰 발견
- 패턴: 14. AI 초안·정답 차이 분류
- 실행 양식: LD 차이 분류

### 2. 분류 근거

현재 형식지에는 AI 초안과 사람 정답본을 비교할 수 있는 신호가 있고, LD가 정답 품질을 알고 있는 것으로 보입니다. 다만 아직 어떤 차이를 규칙으로 넣을지 정리되지 않았기 때문에, 바로 `SKILL.md` 수정으로 들어가기보다 LD가 차이를 먼저 분류하는 단계로 판단했습니다.

### 3. 다음 액션

AI 초안과 사람 정답본을 나란히 비교할 수 있는 자료부터 준비합니다. 그다음 LD가 차이 유형을 판단할 수 있게 차이 목록을 만들고, 규칙 반영은 차이 분류가 끝난 뒤 검토합니다.

### 4. 주의사항

LD 분류 없이 AI가 바로 규칙을 만들면 없는 규칙이 생길 수 있습니다. `(b) 습관`, `(c) 케이스바이케이스`, `보류` 항목은 `SKILL.md` 규칙으로 넣으면 안 됩니다. 신규 규칙 0개도 정상 결과로 인정해야 합니다.

### 5. 회고 안내 (선택 입력)

세션 후 추천한 영역·패턴이 맞았는지, 같이 진행된 다른 영역이 있었는지, SKILL 기준을 고쳐야 할 지점이 있었는지 남길 수 있습니다.
```

## 6. 작성 원칙

### 6-1. 최종 출력은 사람용으로 짧게 쓴다

- 최종 출력은 세션 담당자가 읽는다.
- 내부 사전의 모든 항목을 노출하지 않는다.
- 다음 행동이 바로 보이게 쓴다.
- `분류 근거`, `다음 액션`, `주의사항`은 긴 목록보다 짧은 문단이 더 적합할 수 있다.

### 6-2. 기술용어는 가급적 지양한다

- 세션 담당자와 LD가 바로 이해할 수 있는 표현을 우선한다.
- 단, `LLM`은 팀에서 쓰는 기본 용어로 보고 기술용어 회피 대상에 넣지 않는다.
- 원문 패턴명에 들어간 용어는 임의로 바꾸지 않는다.
- 원문 용어가 어려울 때는 이름을 대체하지 말고, 설명 문장에서 쉬운 말로 풀어 쓴다.
- 예: `휴먼인더루프형`은 패턴명으로 유지하고, 설명에서 “LLM 흐름 안에 LD 판단·선택·검수 지점을 둔다”라고 쓴다.

### 6-3. 내부 사전은 기본 압축 양식으로 쓴다

- 내부 사전은 AI가 판단할 데이터다.
- 적용 신호뿐 아니라 비적용 신호도 반드시 적는다.
- 비적용 신호는 새로 창작하지 않고, 기존 37개 실행 양식의 `판단 기준`과 `주의`에 섞여 있는 내용을 분리 추출한다.
- 적용 신호와 비적용 신호가 짝이 되도록, “이 실행 양식이 맞는 경우”와 “비슷해 보이지만 이 실행 양식이 아닌 경우”를 갈라 쓴다.
- 비적용 신호는 개수를 채우기 위해 억지로 만들지 않는다. 기존 본문에서 명확히 분리되는 경우만 작성한다.
- 비적용 신호가 부족하면 빈칸을 추정으로 채우지 말고, `정보 부족 시 확인 질문`에 확인할 내용을 남긴다.
- 각 비적용 신호는 “이 경우에는 이 실행 양식을 추천하지 않는다”로 판단 가능한 문장으로 쓴다.
- 오분류 위험과 헷갈리는 패턴은 `주의사항`에 합쳐 적는다.
- 정보 부족 시 확인 질문을 넣어 AI가 억지로 분류하지 않게 한다.
- 패턴 경계가 복잡하거나 위험도가 높은 실행 양식만 확장 항목을 추가한다.

### 6-4. 정보 부족 시 확인 질문은 적용 판단에 필요한 빈 정보를 묻는다

`정보 부족 시 확인 질문`은 SKILL이 정보 부족 상태에서 억지로 실행 양식을 추천하지 않도록 두는 안전장치다.  
질문은 세션 담당자가 LD에게 그대로 물어볼 수 있는 문장으로 쓴다.

- 질문은 일반 설문이 아니라, 해당 실행 양식을 적용해도 되는지 판단하기 위해 부족한 정보를 확인하는 질문이어야 한다.
- 질문은 `구현_패턴_사례.md`와 각 실행 양식의 `적용 신호`, `비적용 신호`, `필요한 입력값`, `판단 기준`, `주의사항`, `대표 사례`에 근거해 만든다.
- 문서에 없는 패턴 해석이나 새로운 판단 기준을 임의로 만들지 않는다.
- 특정 단어가 나오는지 묻지 않는다. 단어가 아니라 적용 가능 여부를 가르는 자료, 기준, 비교 대상, 판단 가능 상태를 묻는다.
- 정답본, AI 초안, 원본 데이터, 기존 규칙, 비교 대상, 산출 기준, LD 판단 시간, 검증 기준처럼 구체적으로 확인 가능한 대상을 묻는다.
- 비적용 신호가 있으면 그 상태가 실제로 있는지 LD에게 확인하는 질문으로 바꾼다.
  - 예: `사람 정답본이 없다` → `사람이 만든 정답본이 있나요?`
- 이미 입력 문서에 명시된 사실은 다시 묻지 않는다. 적용 판단에 필요한데 아직 확인되지 않은 정보만 질문으로 남긴다.
- 질문은 실행 양식마다 3~5개를 기본으로 한다. 개수를 채우려고 근거 없는 질문을 만들지 않는다.
- 질문에 답하면 적용 신호, 비적용 신호, 필요한 입력값, 판단 기준 중 무엇이 확인되는지 드러나야 한다.

별도의 질문 리스트 문서로 작성할 때는 아래 형식을 따른다.

```md
# 정보 부족 확인 질문 [범위]

> 대상: `[대상 실행 양식 파일명]`
> 목적: 세션 담당자가 LD에게 직접 물어볼 수 있는 질문만 모은 1차 리스트

## [번호]. [실행 양식명]

### 정보 부족 시 확인 질문

- [질문]
- [질문]
- [질문]
```

### 6-5. 내부 사전 작성 단위는 실행 양식이다

- 영역은 큰 문제 영역이다.
- 패턴은 패턴 묶음 또는 라우팅 단위다.
- 실행 양식은 실제 실행 단위이자 내부 사전의 본체다.

### 6-6. 링크로 자동 변환하지 않는다

- `SKILL.md`는 웹 링크가 아니라 파일명 또는 개념명이다.
- Notion에서 `[SKILL.md](http://skill.md/)`처럼 바뀌면 `SKILL.md`로 되돌린다.

### 6-7. 단계 추정은 추정으로 표시한다

- 세션 입력만으로 현재 단계를 100% 확정하기 어렵다.
- 따라서 최종 출력에는 `현재 단계`가 아니라 `현재 단계 추정`이라고 쓴다.
- 단계 추정 근거는 `분류 근거`에 함께 적는다.
