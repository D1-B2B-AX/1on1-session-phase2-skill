## 패턴 13. 수동 영역 보존

> **영역**: 5. 자동화 한계 인정 · **빈도**: ★★ · **흡수**: #29 자동화 비대상 인정

### 기본 분류
- 영역: 5. 자동화 한계 인정
- 패턴: 13. 수동 영역 보존
- 실행 양식: 자동화 비대상 분리

### 한 줄 기준

일부 영역은 데이터 부족·개인 스타일·구두 정보·강의별 특수성 때문에 자동화하지 않는 것이 맞을 때 적용한다.

### 적용 신호

- 데이터가 1~2건뿐이다.
- LD 개인 운영 idiom이 강하다.
- LLM이나 코드가 읽을 수 없는 정보가 많다.
- 자동화하면 오히려 잘못 고칠 위험이 크다.
- FP 위험이 크다.

### 비적용 신호

- 반복 데이터가 충분히 쌓여 있고 규칙화할 수 있다.
- 개인 스타일이 아니라 명확한 조건으로 설명된다.
- 사람이 봐야 하는 구두 정보나 읽을 수 없는 정보가 없다.
- 자동화 비대상이 아니라 Fresh 검증으로 확인할 일반 룰 후보다.

### 필요한 입력값

- 자동화 실패 사례 / 비정형·구두·개인 스타일 데이터 / FP 위험 / 사람 검수 영역 / 다음 재검토 조건

### 판단 기준

- 데이터가 1~2건뿐이다.
- LD 개인 운영 idiom이 강하다.
- LLM이나 코드가 읽을 수 없는 정보가 많다.
- 자동화하면 오히려 잘못 고칠 위험이 크다.
- 자동화 비대상을 인정하는 것은 포기가 아니라 도구 신뢰도를 지키는 결정이다.

### 추천 액션

- 실행 시점: 룰화·자동화 후보 중 위험하거나 근거가 부족한 항목이 나온 때
- 실행 주체: 세션 담당자와 LD
- 액션 내용: 자동화 비대상 목록·이유·사람 검수 영역·다음에 누적되면 재검토할 후보 나눔. 비대상 영역은 숨기지 말고 검증 문서에도 남김
- 완료 기준: 자동화 비대상 목록과 이유·사람 검수 영역·재검토 조건 정리

### 주의사항

- 오분류 위험: 비대상 영역을 숨기면 검증 단계에서 실패처럼 보임
- 헷갈리는 패턴: Stage·HITL 도구 분담의 HITL 갈래(패턴 1) — 자동화 비대상은 자동화하지 않는 영역을 남기는 것, HITL은 자동화 흐름 안에 사람 선택 지점 설계
- 쓰면 안 되는 조건: 충분히 반복되고 조건이 명확한 항목을 검토 없이 비대상으로 빼는 경우
- 추가 주의: 자동화 비대상 인정은 포기가 아니라 신뢰도 유지 결정

### 대표 사례

- 손승완: lecture-specific 용어와 쉼표 스타일은 검수자 영역으로 남김
- 이현진 운영일지: 셀 색상·구두 합의·LD별 운영 방식은 결정론 도구가 흡수 못 하는 영역으로 인정

### 정보 부족 시 확인 질문

- 이 항목은 데이터가 몇 건이나 쌓여 있나요?
- 개인 스타일이나 구두 합의처럼 도구가 읽기 어려운 정보인가요?
- 자동화하면 잘못 고칠 위험이 있나요?
- 사람 검수 영역으로 남겨야 하는 이유를 설명할 수 있나요?
- 어떤 데이터가 더 쌓이면 다시 자동화 후보로 볼 수 있나요?
