## 패턴 14. AI 초안·정답 차이 분류

> **영역**: 6. diff 룰 발견 · **빈도**: ★★ · **흡수**: #2 Diff 플레이 + #28 Prompt 6규칙

### 기본 분류
- 영역: 6. diff 룰 발견
- 패턴: 14. AI 초안·정답 차이 분류
- 실행 양식: (2 갈래) LD 차이 분류 / 규칙 생성 제한

### 한 줄 기준

AI 초안과 사람 정답본의 차이에서 사람 암묵지를 룰로 번역하되, 추정 룰 생성은 제한해야 할 때 적용한다.

### 적용 신호

**공통**
- AI 초안과 사람이 만든 정답본이 있다.
- 두 결과물 사이에 반복적인 차이가 보인다.

**LD 차이 분류 (#2)**
- 사람이 정답 품질을 알고 있다.
- LD가 "왜 이렇게 고쳤는지" 판단할 수 있다.
- 차이를 규칙으로 바꾸면 다음 실행 품질이 좋아질 가능성이 있다.

**규칙 생성 제한 (#28)**
- diff 분류 결과가 있고, 기존 `SKILL.md`와 신규 규칙 후보가 있다.
- `(b) 습관`·`(c) 케이스바이케이스`·`보류`가 규칙으로 들어가면 안 된다.
- "적절히"·"자연스럽게"·"필요시" 같은 형용사 룰이 생길 위험이 있다.
- 신규 규칙 0개도 허용해야 한다.

### 비적용 신호

**LD 차이 분류 (#2)**
- 사람 정답본이 없거나 AI 초안과 비교할 자료가 없다
- 차이가 단순 오탈자 수준이거나 일회성 수정뿐이다
- LD가 차이마다 *왜 그렇게 했는지* 판단할 시간을 낼 수 없다
- 이미 규칙이 명확히 정리되어 있어 새 규칙 도출이 필요 X

**규칙 생성 제한 (#28)**
- diff 분류 결과가 아직 없다 (LD 차이 분류 갈래가 먼저 필요)
- 신규 규칙 후보가 이미 모두 `(a) 조건 명확`으로 검토된 상태
- 기존 `SKILL.md`와 중복 여부를 점검할 수 없는 상태
- 규칙을 반드시 추가해야 한다는 외부 압박만 있고 본질적 필요는 X

### 필요한 입력값

**공통**: AI 초안 / 사람 정답본 / 차이 목록 / 기존 `SKILL.md`·규칙 문서
**LD 차이 분류**: 사람이 차이마다 "왜 이렇게 했는지" 직접 판단할 시간 / 차이 분류 기준
**규칙 생성 제한**: diff 분류 결과 / 신규 규칙 후보 / 보류 항목 / 실패 항목

### 판단 기준

- 사람이 정답 품질을 알고 있고, 결과물은 안정적으로 만들지만 기준을 말로 다 설명하지 못한다.
- AI 결과와 사람 결과의 차이가 반복적으로 나타난다.
- `(b) 습관`·`(c) 케이스바이케이스`·`보류`가 규칙으로 들어가면 안 된다.
- 형용사 룰은 실행성이 약하다 / 신규 규칙 0개도 정상 / 기존 지침 중복 금지.
- 단일 프롬프트로 "차이 보고 규칙 만들어줘" 시키면 Claude가 추정 규칙 만들 위험이 큼.

### 추천 액션

- 실행 시점: AI 초안과 사람 정답본의 차이 목록을 만든 후(LD 차이 분류) / diff 플레이 후 신규 규칙 후보를 `SKILL.md`에 반영하기 전(규칙 생성 제한)
- 실행 주체: LD(차이 분류) / 세션 담당자·AI(규칙 생성 제한)
- 액션 내용:
  - **LD 차이 분류**: 각 차이를 `(a) 조건 명확` / `(b) 습관` / `(c) 케이스바이케이스` / `보류` / `공동탐색`으로 분류. `(a)`만 `SKILL.md` 규칙 후보로 넘김. 나머지는 보류·사람 판단 영역으로 남김
  - **규칙 생성 제한**: 운영 원칙·신규 규칙·보류 항목·실패 항목 나눔. 신규 규칙은 최대 5개까지·`(a) 조건 명확` 아닌 항목과 기존 지침 중복은 제외
- 완료 기준:
  - **LD 차이 분류**: 모든 차이에 LD 분류값과 판단 이유가 붙고, 규칙 후보(`(a) 조건 명확`)와 미반영 항목(보류·습관·케이스바이케이스)이 분리된다
  - **규칙 생성 제한**: 신규 규칙(최대 5개)·보류 항목·실패 항목이 분리되고, 신규 규칙 0개도 허용된 상태로 정리된다

### 주의사항

- 오분류 위험: diff 추출과 규칙 생성을 한 번에 시키면 가짜 규칙이 늘어남 / "규칙을 꼭 만들어야 한다"는 압박이 품질 떨어뜨림
- 헷갈리는 패턴: Fresh 검증(패턴 12) — Diff 플레이는 규칙 만들기 전 차이를 분류하는 단계, Fresh 검증은 이미 만든 룰이 새 자료에서 안전한지 보는 단계
- 쓰면 안 되는 조건: 사람 정답본 없거나 LD가 차이 판단할 시간 없으면 적용 X / `(b) 습관`·`(c) 케이스바이케이스`·`보류`를 규칙으로 넣는 경우
- 추가 주의: 신규 규칙 0개도 정상 결과 / 기존 지침 중복도 금지

### 대표 사례

- **LD 차이 분류**: 조여경 `/deploy-notice`와 실제 배포공지 차이를 여경님이 `(a)/(b)/(c)/보류`로 분류·Claude는 `(a)`만 규칙으로 번역 / 손승완 원본 SRT와 정답본 docx 차이를 사전·정규식·Few-shot·LLM pass에 배정
- **규칙 생성 제한**: 조여경 diff 플레이 후 Prompt ②에 6규칙 걸어 `(a)` 조건 명확한 답만 규칙화·결과 신규 규칙 0건이라는 정직한 결과
