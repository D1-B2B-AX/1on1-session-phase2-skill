## 패턴 9. 학습→구현→진화 3단계

> **영역**: 3. LD 자립 빌더 · **빈도**: ★★ · **흡수**: #3 체크리스트+프롬프트 + #24 자력 빌더 3단계 + #30 작은 루틴 직접 AX

### 기본 분류
- 영역: 3. LD 자립 빌더
- 패턴: 9. 학습→구현→진화 3단계
- 실행 양식: (3 갈래) 체크리스트+프롬프트 실행 / 자력 빌더 단계 전환 / 작은 루틴 AX 설계

### 한 줄 기준

LD가 도구 사용자에서 도구를 직접 진화시키는 사람으로 넘어가야 할 때 적용한다.

### 적용 신호

**공통**
- 한 번 만들어주는 것으로 끝나면 확산이 안 된다.
- LD가 AI에게 좋은 질문·판단을 주는 법을 배워야 한다.
- 코치가 점점 뒤로 빠져야 한다.

**체크리스트+프롬프트 (#3)**: LD가 자기 Claude에서 단계별로 직접 실행해야 함 / 진단·처방·구현·검증·효율 측정·다음 액션을 단계별로 나눌 수 있음
**자력 빌더 단계 전환 (#24)**: LD가 직접 판단할 diff·룰·검증 과제가 있음 / "명확해서 혼자 해볼 수 있을 것 같다" 같은 자력 신호
**작은 루틴 AX (#30)**: 30분~1시간짜리 작은 반복 업무 / AX팀이 매번 대신 만들어줄 수 없음 / LD가 작은 자동화를 계속 직접 만들 수 있어야 함

### 비적용 신호

**체크리스트+프롬프트 실행 (#3)**
- LD가 직접 실행·학습할 필요 없이 세션 담당자가 일회성 산출물만 만들면 됨
- 작업의 핵심이 프롬프트 실행이 아니라 데이터 구조·계산 로직·권한 문제 해결에 있다
- 단계별로 나눌 만큼 업무가 복잡하지 않고 단일 질문으로 충분
- LD 자립보다 빠른 대리 구현이 더 중요한 긴급 상황

**자력 빌더 단계 전환 (#24)**
- LD가 직접 도구를 진화시킬 필요 없는 일회성 작업
- 코치가 계속 대신 Claude를 돌리는 구조이고 변경 의사 X
- 적용 범위·over-fit·검증 기준 이해 없이 단독 자력으로 넘기려는 상황
- LD가 사용할 AI 환경·실행 권한이 없어 단계 전환 자체가 불가능

**작은 루틴 AX 설계 (#30)**
- 한 번만 처리하면 되는 일회성 업무
- 반복 주기나 소요 시간이 불명확해 ROI 잣대 자체가 없다
- LD가 직접 만들 필요 없이 중앙에서 큰 시스템으로 해결해야 하는 영역
- 완전 자동화보다 초안+수동 5분 복붙이 더 낫다는 판단을 하지 않은 상태

### 필요한 입력값

**공통**: 현재 스킬·코드·문서 / LD가 사용할 AI 환경
**체크리스트+프롬프트**: 단계별 목표(진단·처방·구현·검증·효율 측정·다음 액션) / 코치 작성 프롬프트 묶음 / 경계 문장(수정 금지·진단만·구현 전 계획 제시)
**자력 빌더 단계 전환**: 초기 도구 / 코치 시범 프롬프트 / LD 자력 수행 과제 / 단계 전환 신호
**작은 루틴 AX**: 반복 주기·현재 소요 시간 / 사람이 이미 알고 있는 정답 품질 / 분기 가능한 규칙 / 출력 포맷

### 판단 기준

- 한 번 만들어주는 것으로 끝나면 확산이 안 된다.
- 코치는 점점 뒤로 빠져야 한다.
- 단독 자력으로 넘어가기 전 적용 범위·over-fit·검증 기준 이해 필요.
- ROI상 완전 자동화보다 초안+수동 5분 복붙이 더 나을 수도 있다 (작은 루틴 AX).

### 추천 액션

- 실행 시점: LD가 도구를 직접 수정·진화시켜야 하는 과제가 생긴 때
- 실행 주체: 세션 담당자(코치)와 LD
- 액션 내용:
  - **체크리스트+프롬프트**: LD가 자기 Claude에서 순서대로 실행할 프롬프트 묶음 만듦. 각 프롬프트에 목적·수정 가능 여부·필요한 입력·기대 출력·완료 기준 포함
  - **자력 빌더 단계 전환**: 1차 받아쓰는 사용자·2차 같이 빌더 학습·3차 LD 단독 자력 사이클로 단계 나눔. 각 단계마다 LD 직접 판단 과제 붙임·3차 진입 신호 확인
  - **작은 루틴 AX**: 반복 주기·현재 소요 시간·분기 규칙·출력 포맷 정리. 분기 트리·출력 포맷 만들고 diff 플레이와 자력 개선 숙제·Validation 1 Core 붙임
- 완료 기준:
  - **체크리스트+프롬프트 실행**: LD가 진단·처방·구현·검증·다음 액션을 순서대로 실행할 수 있는 프롬프트 묶음과 체크리스트가 준비된다. 각 프롬프트에 목적·수정 가능 여부·필요한 입력·기대 출력·완료 기준이 포함된다
  - **자력 빌더 단계 전환**: 현재 LD 단계(1차 받아쓰기 / 2차 공동 빌더 / 3차 단독 자력)·다음 단계 과제·3차 진입 신호가 정리된다
  - **작은 루틴 AX 설계**: 분기 트리·출력 포맷·LD 자력 개선 숙제·Validation 1 Core 검증 기준이 정리된다

### 주의사항

- 오분류 위험: LD가 직접 실행 안 하면 자력 빌더 전환 약해짐 / 코치가 대신 Claude 돌리면 결과물 주인이 코치에게 남음 / 작은 업무라고 설계 대충 하면 재사용 X
- 헷갈리는 패턴: 갈래끼리 — 체크리스트+프롬프트는 당장 실행할 문장 묶음, 자력 빌더 단계 전환은 LD 역할 변화의 장기 단계, 작은 루틴 AX는 대상 업무 크기·반복성에 초점
- 쓰면 안 되는 조건: 수정 금지 단계에서 구현 프롬프트 바로 실행 / 적용 범위·over-fit·검증 기준 이해 전 단독 자력 / 반복 주기·소요 시간 미확인

### 대표 사례

- **체크리스트+프롬프트**: 안유진B·조여경·손승완 (단계별 프롬프트로 학습)
- **자력 빌더 단계 전환**: 김동찬 (1차 스키마·2차 `/validated-plan`·3차 폐강 위험 기능 단독) / 손승완 (v1·v2~v5·v6~v9) / 안유진B (윤지가 프롬프트 주되 유진님 Claude에서 직접 실행)
- **작은 루틴 AX**: 조여경 격주 30분~1시간 배포공지 업무를 `/deploy-notice`로 자동화. 핵심은 도구 하나보다 "작은 업무를 LD가 직접 AX화하는 방법"
